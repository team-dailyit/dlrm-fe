# js-test

테스트 컨벤션에 맞춰 테스트를 작성하고, 실행해서 결과를 확인한다.

## 1단계: 컨벤션 확인

`docs/test-convention.md`를 읽고 따른다.

## 2단계: 테스트 대상 파악

- 테스트할 코드(SUT)의 공개 인터페이스를 파악한다. 내부 구현이 아니라 공개 인터페이스를 기준으로 케이스를 정한다.
- 우리가 구현한 동작과 라이브러리가 보장하는 동작을 구분하고, 우리가 구현한 동작만 케이스로 잡는다.
- 이미 있는 테스트 파일이면 먼저 읽고, 같은 동작을 검증하는 테스트가 있는지 확인한다.
- 테스트하기 어려운 구조라면 테스트를 억지로 작성하지 말고, 테스트 가능하도록 리팩터링하는 방법을 사용자에게 제안한다.

## 3단계: 테스트 작성

- 구현 파일 옆에 `*.test.ts(x)`로 작성한다.
- 작성할 케이스 목록이 길거나 애매하면, 작성 전에 케이스 목록을 사용자에게 보여주고 확인받는다.

## 4단계: 실행 및 확인

- 작성한 테스트 파일만 실행한다. (예: `pnpm --filter service exec vitest run <파일 경로>`)
- 실패하면 원인이 테스트인지 구현인지 구분해서 보고한다. 구현 버그로 보이면 임의로 구현을 고치지 않고 사용자에게 확인받는다.
- 새 기능을 테스트부터 작성하는 경우에는, 구현 전에 테스트가 의도한 이유로 실패하는지 먼저 확인한다.

## 완료 후

- 추가·수정한 테스트 케이스와 실행 결과(통과 수)를 요약해서 보고한다.
