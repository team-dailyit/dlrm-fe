# js-test

테스트 컨벤션에 맞춰 테스트를 작성하고, 실행해서 결과를 확인한다.

## 1단계: 컨벤션 확인

`docs/test-convention.md`를 읽고 테스트 컨벤션을 따른다.

## 2단계: 테스트 케이스 정리

- 테스트할 코드(SUT)를 읽고, 컨벤션에 따라 검증할 케이스 목록을 만든다.
- 이미 있는 테스트 파일이면 먼저 읽고, 같은 동작을 검증하는 테스트가 있는지 확인한다.
- 케이스 목록이 길거나 애매하면, 작성 전에 사용자에게 보여주고 확인받는다.
- 테스트하기 어려운 구조라면 테스트를 억지로 작성하지 않고, 리팩터링 방법을 사용자에게 제안한다.

## 3단계: 테스트 작성

컨벤션에 맞춰 테스트를 작성한다.

## 4단계: 실행 및 확인

- 작성한 테스트 파일만 실행한다. 경로는 앱 디렉토리 기준이다.
  - 예: `pnpm --filter service exec vitest run src/shared/api/apiClient.test.ts`
  - 어드민은 `--filter admin`을 쓴다.
- 실패하면 원인이 테스트인지 구현인지 구분해서 보고한다. 구현 버그로 보이면 임의로 구현을 고치지 않고 사용자에게 확인받는다.

## 완료 후

- 추가·수정한 테스트 케이스와 실행 결과(통과 수)를 요약해서 보고한다.
